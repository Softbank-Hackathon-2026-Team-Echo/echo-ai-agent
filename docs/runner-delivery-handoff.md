## WAS #123 회신 초안 — R09

러너 쪽 전송 실패 보완을 독립 변경으로 구현했습니다. 이벤트는 `data` 전체 JSON 2,000자·요청 100건/UTF-8 1MiB 이내로 보내고, 확정 422에는 같은 순번의 요약을 한 번 보냅니다. 요약도 거절/미확인이면 이벤트 채널만 중단하고 결과는 계속 제출합니다.

진단/적용 결과의 확정 422에는 패치·성공 커밋 없는 FAILED/RUNNER_ERROR를 제출합니다. 네트워크/429/5xx 등은 같은 결과만 총 3회 이내 재전송하고, 409·권한·임대 상실은 중단합니다. 수락 응답을 확인하지 못하면 로컬에 미확인으로 기록하며 모델·샌드박스·GitHub 쓰기를 다시 실행하지 않습니다.

로컬 러너 전체 490건, 실제 WAS main 87966f7 전체 2,947건(신규 계약 4건 포함), #135 관련 216건과 새 러너 계약 4건, 기존 프론트 366건·빌드가 통과했습니다. 실패 결과에서 새 배포/작업이 생성되지 않음과 DB 저장 후 응답 유실→409 기존 결과 보존까지 확인했습니다. 이 시험은 WAS 저장소/재배포 자동복구 검증이 아닙니다.

운영 API·worker의 실제 진단/패치 적용 on·simulate off를 재확인했고, API의 수정 커밋 반영도 on입니다. 기존 11/7 18:28 실행은 수정 커밋 d387b612 → 재배포 7d7e462c → 실제 성공 근거가 있습니다. 새 코드의 GCP 후보 검증은 488 PASS/2 SKIP(해당 2건은 로컬 PASS)입니다. 사용자 최신 지시대로 운영 release는 0d10ac1로 유지했고 새 종단 배포는 실행하지 않았습니다.

## 도영님 화면 연결 초안 및 시험 사례

#106의 같은 화면 재배포 표시를 유지하고 #135의 `patches[].apply.followUp`을 읽도록 확장하면 됩니다. 기존 `src/lib/api/prechecks.ts`의 2초 조회·90초 예산을 재사용하되, 아래 상태를 분리해주세요. 러너 변경을 기다려야 하는 새 필드는 없습니다.

| 입력/상황 | 화면·조회 인수 조건 |
|---|---|
| apply 진행 중 | 샌드박스 검증 진행. 저장소/재배포 완료로 표시하지 않음 |
| repository PENDING/IN_PROGRESS | 저장소 반영 대기/진행. 예약/자동복구 보장 문구 없음 |
| repository SUCCEEDED | 저장소 반영 완료. 실제 배포 성공과 별개 |
| repository UNKNOWN / REPO_WRITE_FAILED | 확인 필요. 자동 재전송 버튼이 POST를 호출하지 않음 |
| redeploy CREATED + 유효 ID | 새 배포 GET·로그를 같은 화면에 연결. 접수만 완료 |
| 새 배포 최종 SUCCEEDED | 모의 아님·수정 commit 일치·원본과 다름을 확인한 경우만 AI 수정본 성공 |
| 모의/COMMIT_DISABLED·원본 SHA 배포 | 원본 재배포/검증 제한을 명시. AI 수정본 성공 금지 |
| apply FAILED 또는 redeploy REJECTED | 실패한 단계와 안전한 코드 표시. 이전 샌드박스 성공을 배포 성공으로 확대하지 않음 |
| 90초 초과·deadlineAt null | ‘결과 확인이 지연되고 있습니다’. 다시 확인은 GET만, 서버 FAILED로 변환하지 않음 |
| followUp 없음/null(구서버) | 기존 ID·거절 코드·apply 실패로 fallback. finishedAt만으로 완료하지 않음 |
| schemaVersion 미지원/모순 ID+거절 | 확인 필요. 같은 대상의 새 GET으로만 재확인 |
| 401/403/404 | 자동 조회 중단. 권한/대상 없음과 작업 실패 구분 |
| 네트워크/429/5xx | 마지막 확인 상태 유지 + 조회 오류 표시, 작업 FAILED로 바꾸지 않음 |
| 조직/화면/패치/apply 바뀐 뒤 이전 응답 | 이전 응답 무시. 동일 대상 GET 직렬화 또는 이전 요청 취소 |
| 유효한 기존 완료 ID가 있는데 오래된 응답 도착 | ID를 되돌리지 않음. updatedAt/schemaVersion을 상태 revision으로 사용하지 않음 |

위 표는 인수 명세이며 **화면 시험을 실행했다는 뜻은 아닙니다**. 최신 frontend origin/main c179ed4의 prechecks.ts는 followUp을 아직 소비하지 않습니다. 새 분기 코드·컴포넌트 시험은 도영님 변경으로 받고, #135 계약 배포 후 실제 브라우저에서 확인합니다.
